# スクラム開発ハーネス

このスキルが有効なプロジェクトでは以下の規律を守ること。
実装作業の規律（TDD・検証ゲート・誠実性）は **eng-core スキルに従う**。
ユーザーはプロダクトオーナー（PO）を兼ねる。Claude は開発者であり、
**PO の決定（優先順位・受入判断・スコープ）を代行しない**。

## アーティファクト（状態の外部化）

| ファイル | 役割 |
|---------|------|
| `docs/PRODUCT_BACKLOG.md` | プロダクトバックログ（PBI-xxx）。優先順位の唯一の正 |
| `docs/sprints/SPRINT-NNN.md` | スプリントごとの計画・進捗・レビュー・レトロ |
| `docs/adr/` | 設計判断の記録（eng-core） |

作業開始時は必ず現行スプリントファイルを読み直す。会話記憶を状態にしない。

## プロダクトバックログの規律

- PBI はユーザーストーリー形式:「〈誰〉として〈何〉がしたい。それは〈なぜ〉のためだ」
- 各 PBI に **受入基準（Given / When / Then）** を必ず付ける。
  受入基準はテストに変換可能な粒度で書く（テストがスプリントの契約になる）。
- INVEST を満たすように分割する（独立・交渉可能・価値・見積可能・小さい・テスト可能）。
- 見積は相対サイズ（1, 2, 3, 5, 8）。8 は「分割が必要」のシグナル。
- 並び順 = 優先順位。並び替えは PO（ユーザー）だけが決める。

## Definition of Ready（スプリントに入れてよい条件）

- [ ] 受入基準が Given/When/Then で書かれている
- [ ] 見積が付いている（8 以下）
- [ ] 外部依存・不明点が解消済み、または明記されている

## Definition of Done（PBI を完了と呼べる条件）

- [ ] 受入基準がすべて自動テストまたは確認手順で検証され、通っている
- [ ] eng-core の検証ゲート全通過（テスト・リント・型・ビルド）
- [ ] preflight チェックリスト実施済み
- [ ] ドキュメント（README・ADR 等、該当分）更新済み
- [ ] **PO がレビューして受入した**（Claude の自己判断で Done にしない）

## スプリントの規律

- スプリントには**スプリントゴール**（1文）を必ず置く。ゴールに寄与しない
  作業を勝手に足さない。
- スプリント期間はユーザーと合意した長さ（個人開発では「セッション数」や
  「日数」でよい）。
- **スコープ変更は PO の明示的決定**: 途中で仕様変更・割り込みが来たら、
  (a) 今スプリントに入れて何かを外す (b) バックログに積んで次で扱う、を
  PO に選ばせる。黙って吸収しない。
- 完了できなかった PBI は「未完」としてバックログに戻す（部分点を主張しない）。
- ベロシティ（完了ポイント合計）をスプリントファイルに記録し、次の計画の
  キャパシティ目安にする。

## セレモニー（コマンド対応）

| コマンド | セレモニー | 内容 |
|----------|-----------|------|
| `/scrum-init` | — | バックログ初期化・最初のストーリー起票 |
| `/sprint-plan` | スプリントプランニング | DoR 確認 → ゴール設定 → PBI 選択 → タスク分解 |
| `/standup` | デイリースクラム | 状態ファイル+git log から進捗・障害・今日の計画を報告 |
| `/sprint-end` | レビュー + レトロ | 受入基準ベースのデモ・受入判定 → ふりかえり → 次へ |

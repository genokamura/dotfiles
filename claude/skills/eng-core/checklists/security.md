# セキュリティチェックリスト（認証・認可・決済・個人情報・外部入力に触れる変更）

STRIDE の簡易版。該当する観点だけでよいが、「該当なし」の判断も明記する。

## なりすまし（Spoofing）
- [ ] 認証が必要な操作に認証チェックがある（API・画面の両方）
- [ ] セッション/トークンの有効期限・失効処理がある

## 改竄（Tampering）
- [ ] 外部入力（クエリ・ボディ・ヘッダ・ファイル名・URL）を境界で検証している
- [ ] SQL/コマンド/パス/HTML の組み立てにパラメタライズ・エスケープ機構を使用
- [ ] クライアント側の値（価格・権限フラグ等）をサーバ側で信頼していない

## 否認（Repudiation）
- [ ] 重要操作（権限変更・削除・決済）に監査ログがある
- [ ] ログに秘密情報・個人情報が出力されない

## 情報漏洩（Information Disclosure）
- [ ] エラーメッセージが内部構造（スタックトレース・SQL・パス）を漏らさない
- [ ] 秘密情報は環境変数/シークレット管理からのみ取得している
- [ ] 権限のないレコードへの直接参照（IDOR）ができない

## サービス妨害（DoS）
- [ ] サイズ・件数・レート・タイムアウトの上限がある（入力・ループ・外部呼び出し）

## 権限昇格（Elevation of Privilege）
- [ ] 認可チェックはリソース単位（「ログイン済みか」だけでなく「その人のものか」）
- [ ] デフォルトは拒否（許可リスト方式）

## 依存関係
- [ ] 追加した依存は必要最小限で、既知の脆弱性がない（audit 系コマンドを実行）
- [ ] lockfile を更新し、意図しないバージョン変動がない

description: スプリントバックログを開発エージェントチーム（実装/レビュー/QA）で実行する。人間は5つの決定クラスの判断のみ
---

scrum スキル・eng-core スキル・~/.claude/skills/scrum/agent-team.md
（調停プロトコル）を読み込み、現行スプリントのタスクボードをエージェント
チームで消化してください。

引数（任意・対象タスクや同時実行数の指定）: $ARGUMENTS

あなた（メインセッション）は**オーケストレーター**です。自分ではコードを
書かず、分解・割当・調停・統合・エスカレーションに徹すること。

手順:
1. docs/sprints/ の現行スプリントファイルを読む。タスクボードが無い・
   粒度が粗い場合は、先にタスク分解して PO に一覧を見せる。
2. ボードから実行可能なタスク（depends 解消済み・対象が重ならない）を選ぶ。
3. agent-team.md のパイプラインに従い実行する:
   - ボードに割当を書き込んでから dev-implementer をディスパッチ
     （並列時は worktree 分離。プロンプトは agent-team.md の
     **コンテキストパケット規約**に従って組み立てる: task/why/scope/
     inputs/constraints/output を全量、最初の1ターンで渡す）
   - 完了報告 → dev-reviewer で敵対的レビュー（差し戻し最大2回）
   - approve → qa-verifier でゲート・受入基準を実行検証
   - pass → 統合し、ボードを「統合済み」に更新
4. 状態遷移のたびに1行ログを出す（例: `TSK-03 実装中→レビュー中`）。
5. 以下は必ず停止して PO の判断を仰ぐ（agent-team.md の決定クラス）:
   スコープ変更 / 設計判断(ADR級) / 差し戻し上限超過・reject / blocked の
   解消方針 / 破壊的操作・セキュリティ懸念。
   エスカレーションは「状況・選択肢・推奨」を簡潔に提示する。
6. ボードのタスクがすべて「統合済み/受入待ち」になったら、サマリ
   （完了タスク・ベロシティ見込み・human_needed 項目・残ブロッカー）を
   報告し、/sprint-end（PO の受入判定）を案内する。

注意:
- エージェントの報告は鵜呑みにしない。status=done でもボード更新前に
  changed_files と tests の整合を確認する（git log / diff で実在を確認）。
- 途中で中断しても、ボードだけから再開できる状態を常に保つ。

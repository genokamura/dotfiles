description: リポジトリに CI/CD パイプラインを敷く（ローカル=CI パリティ、ステージ分割、ラチェット）
---

tdd-cicd スキルと eng-core スキルを読み込み、このリポジトリの CI/CD
パイプラインを設計・構築してください。

引数（任意・対象環境や CI サービスの指定）: $ARGUMENTS

手順:
1. スタックを検出する（package.json / pyproject.toml / go.mod / Makefile /
   既存の .github/workflows/ 等）。既存 CI がある場合は現状を分析し、
   スキルの原則との差分（CI 固有ロジック・ステージ未分割・retry での
   フレーク隠蔽等）を先に報告する。
2. **ローカルゲートのコマンド群を先に定義する**（Makefile / scripts 等）。
   lint / 型 / unit / integration / build を単一の入口に揃え、実行して
   通ることを確認する。CI はこれを呼ぶだけにする。
3. docs/TEST_STRATEGY.md を生成または更新し、検証コマンド表を確定する。
4. tdd-cicd スキルの templates/github-actions-ci.yml を元に、ステージ分割
   （commit < 10分 → integration → e2e）でワークフローを作成する。
   TODO プレースホルダはステップ2のコマンドで置換する。
5. ラチェットとフレーク方針を設定に反映する（カバレッジ下限は現状値、
   引き下げは人間承認 + 記録。テストの retry 設定を恒久化しない）。
6. main ブランチ保護（required checks）とロールバック手順の設定は人間の
   作業なので、必要な操作を手順として提示する。
7. 可能ならローカルで全ゲートを実行し、結果（実行コマンドと件数）を添えて
   報告する。push 後の初回 CI 実行の確認方法も案内する。

停止点:
- 既存パイプラインの削除・大幅変更は差分を提示して承認を得てから
- デプロイ（CD）部分は対象環境・認証情報が関わるため、設計案の提示までに
  とどめ、適用は人間の確認後

description: 既存テストスイートを古典学派の規律で監査する（実装結合・過剰モック・非決定性の検出、読み取り専用）
---

tdd-cicd スキルを読み込み、このリポジトリのテストスイートを監査して
ください。**読み取り専用** — 修正はせず、指摘と修正提案を返します。

対象（任意・ディレクトリやモジュールで絞り込み）: $ARGUMENTS

検出する違反（tdd-cicd §1・§2）:
1. **相互作用検証**: 所有コードに対する「呼ばれたか」のアサート
   （verify / assert_called / toHaveBeenCalled 等）
2. **境界外モック**: TEST_STRATEGY.md の境界一覧にない箇所のテストダブル、
   所有しない型（サードパーティ）の直接モック
3. **実装結合**: private への到達、内部構造に依存したアサート、
   リファクタで壊れる形のテスト
4. **非決定性**: sleep 待ち・実時刻・実乱数・テスト間の順序依存・
   共有可変状態・環境依存
5. **仕様として読めないテスト**: 意味のない名前、アサーションのないテスト、
   1テストに複数振る舞い
6. **ピラミッドの歪み**: unit で書けるものが E2E にある、逆に結合が必要な
   検証を過剰なモックで unit に押し込めている
7. **フレーク隠蔽**: retry 設定・条件付き skip での握りつぶし

報告形式（coverage-first — 見つけたものは確信が持てなくても全件報告し、
フィルタは読み手に委ねる）:

```
findings:
  - [severity: critical|major|minor / confidence: high|medium|low]
    <ファイル:行> <違反の種類> <根拠> <修正の方向性（fake化・境界注入・層の移動等）>
summary:
  - 件数の内訳と、最も効果の大きい改善3つ
  - TEST_STRATEGY.md への反映提案（境界一覧の追記・隔離リスト等）
```

修正の実施は、ユーザーが選んだ項目について /tdd（再現テスト→修正）で行う。

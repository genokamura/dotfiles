---
description: デイリースクラム — 現行スプリントの進捗・障害・次の作業を状態ファイルと git log から報告する
---

scrum スキルを読み込み、デイリースクラムを実施してください。
これは**セッション再開時の状態復元**を兼ねます。会話記憶ではなく、必ず
ファイルと git の実態から報告すること。

手順:
1. docs/sprints/ の最新スプリントファイルと docs/PRODUCT_BACKLOG.md を読む。
2. `git log --oneline` と `git status` で前回以降の実際の変更を確認する。
3. スプリントファイルのタスクのチェック状態と git の実態がズレていれば、
   実態に合わせて更新する（やった形跡のないタスクを完了にしない）。
4. 以下の形式で簡潔に報告する:
   - **前回からやったこと**（コミット・完了タスク）
   - **今日やること**（次のタスクと、それが終わるとどの PBI が進むか）
   - **障害・懸念**（ブロッカー、スプリントゴール達成へのリスク）
5. スプリントゴールの達成が危うい場合は、その旨と選択肢
   （スコープ調整の相談）を PO に提示する。
